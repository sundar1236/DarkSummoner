# Phase 02 — Shadow Hunter Production Character

Status: ART SOURCE REQUIRED — rig integration not started
Branch: visual-overhaul/phase-01-audit
Target: Godot 4.3, portrait mobile, GL Compatibility

## Objective

Replace the current single flattened Shadow Hunter sprite with a production-ready character presentation that reads clearly at combat scale and supports authored movement and combat animation. Preserve PlayerController, collision, targeting, attack timing, damage, dodge gameplay, skills, saves and character progression.

## Confirmed current implementation

- PlayerController creates a Sprite2D at runtime and loads `assets/sprites/characters/player_shadow_hunter.png`.
- The sprite is scaled to 0.44 in the combat scene.
- CharacterAnimationController animates the whole sprite through transform offsets, scale, rotation and tint.
- The current character image is a flattened 128 x 128 procedural image generated by `tools/generate_phase3_art.gd`.
- Weapon presentation is partly baked into the hero image; the separate weapon Sprite2D is hidden by default.
- The character root is CharacterBody2D and owns movement/collision. This root must remain intact.

## Approved art direction

- Distinctive hooded assassin silhouette; white/silver hair; dark layered leather/cloth; restrained gold trim; violet energy daggers.
- Stylized 2.5D chibi proportions, polished hand-painted/PBR-inspired material treatment, readable three-quarter top-down combat view.
- Clear head, torso, pelvis, upper/lower arms, hands, thighs, lower legs, boots, cape/hood cloth and independent dual daggers.
- Ground-contact shadow is separate from the character art.
- Transparent background; no labels, UI, scenery, floor, border or baked glow behind the character.
- Maintain one consistent scale, lighting direction, pivot convention and palette across every animation frame.

## Required source-art deliverable

Choose exactly one production pipeline:

### Preferred: layered cutout source

Deliver separate transparent PNG layers with consistent canvas size and pivots:
- back_cape
- rear_leg_upper/lower and rear_boot
- front_leg_upper/lower and front_boot
- pelvis_and_torso
- rear_arm_upper/lower/hand
- front_arm_upper/lower/hand
- head_face
- hood_back and hood_front
- hair_back and hair_front
- dagger_left and dagger_right

Parts must overlap naturally at joints; no white matte, baked shadow, or missing joint coverage. Provide a small layer/pivot manifest. A Godot Skeleton2D/Bone2D rig can then be built without cutting a flattened image into fake limbs.

### Alternative: authored sprite sheet

If layered source cannot be provided, deliver a transparent sprite sheet with explicit frame dimensions and metadata. Minimum initial clips: idle (6 frames), 8-direction locomotion (6 frames per direction), 3-stage attack (4 frames per stage), dodge (4), hurt (2), death (6), victory (6), skill (6). All frames must share the same character design, ground anchor and camera angle. Do not use a promo poster, character lineup or UI screenshot as a sprite sheet.

## Godot integration plan after art acceptance

1. Create a reusable visual child scene under the existing CharacterBody2D; do not replace the gameplay root.
2. Add GroundShadow, CharacterVisualRoot, weapon sockets and a dedicated VFX layer.
3. For layered source, use Skeleton2D/Bone2D and AnimationPlayer. Add AnimationTree only if directional blending materially benefits the result.
4. For sprite-sheet source, use SpriteFrames/AnimatedSprite2D or AnimationPlayer frame tracks. Do not create a redundant skeletal rig.
5. Adapt CharacterAnimationController as a gameplay-state adapter that requests idle/run/attack/skill/hurt/dodge/death/victory clips. Keep all gameplay timing and hit logic in PlayerController/combat systems.
6. Keep the old Sprite2D visual as a fallback until the new scene passes validation.
7. Test all eight movement directions, attack interruption, dodge/hurt priority, death, victory, weapon socket alignment and character scale in the actual arena.
8. Profile on Android with GL Compatibility; avoid expensive full-screen effects.

## Acceptance criteria

- Character silhouette and weapon are readable at the existing combat scale.
- No visible limb gaps, detached pivots, clipping, jitter or ground-anchor drift.
- Animation is authored frame/bone motion, not just whole-sprite bob/rotation.
- The single joystick and stationary nearest-enemy auto-attack behave exactly as before.
- No changes to damage, cooldowns, hitboxes, save schema, inventory or progression.
- Existing automated tests pass; Godot editor and Android runtime validation are recorded before merge.

## Current blocker

The repository contains no animation-ready layered Shadow Hunter source or genuine Shadow Hunter sprite sheet. The generated promotional mockup images are not suitable production assets. Do not commit them as character sprites and do not fake a skeletal rig from the flattened 128 x 128 image.

Phase 02 art implementation can proceed as soon as the layered source or a valid sprite sheet exists. Until then, the safe action is to preserve the working combat implementation.
